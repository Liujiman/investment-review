## 11.3 用户事件入口与时间分类

交易导入后，在导入区找到“用户上传事件证据”，表单为“新增事件证据”。按下表逐份保存，每次保存后表单会清空，要重新填写。

| 页面字段 | 事前材料 | 事后材料 | 时间未知材料 |
| --- | --- | --- | --- |
| 上传证据原文（TXT） | event-before.txt | event-after.txt | event-date-only.txt |
| 证据关联证券 | DEMO001 | DEMO001 | DEMO001 |
| 事件标题（必填） | 构造验收：事前材料 | 构造验收：事后材料 | 构造验收：时间未知材料 |
| 事件原始摘录（必填） | 上传后保留整个文件内容 | 同左 | 同左 |
| 证据来源名称（必填） | 用户提供的构造验收材料 | 同左 | 同左 |
| 证据原文链接（可选） | 留空 | 留空 | 留空 |
| 首次发布时间精度 | 日期与时刻 | 日期与时刻 | 仅日期 |
| 原始首次公开日期 | 2025-03-10 | 2025-03-10 | 2025-03-10 |
| 原始首次公开时刻（上海） | 09:30:00 | 18:00:00 | 不出现，不填写 |
| “我确认摘录对应当时版本；当前修订后的文字不能仅凭旧发布日期成为事前依据。” | 勾选（仅构造版本声明） | 勾选（仅构造版本声明） | 勾选（仅构造版本声明） |

每份操作顺序：上传对应TXT → 确认原文和构造声明仍在摘录中 → 填写证券、标题、来源，链接留空 → 选择精度 → 填日期及有依据的时刻 → 勾选版本声明 → 点击“保存新增事件证据” → 等待保存成功。TXT只填入摘录，不自动解析标题、来源、日期或时刻。所有文件都在 `docs/acceptance-fixtures/`，UTF-8文本。

在“02 时间线与统一证据”的“选中决策交易”选择 **DEMO001 · 2025-03-10T10:00:00+08:00 · 买入** 对应项（通常默认即此项）。用“证据可见范围”逐项观察：

- “全部记录（含事后，不是事前评估）”：两笔交易加三条事件，共5条；事件分别为事前可知、事后信息、时间未知。当前买入成交结果和后续卖出都是事后信息，总体分类为1/3/1。
- “事前可知”：只显示09:30材料，不展示完整过程的事后盈亏。
- “事后信息”：18:00材料和两笔交易，共3条。
- “时间未知”：只有仅日期材料，不能出现补造的午夜时刻。

此CSV不会自动填入理由或行情。上午不能使用当天完整收盘日线；该规则已有自动测试，此人工案例没有行情导入入口，不声明此次人工上传验证了日线。不要改用其他时点后仍套用以上数量。

## 11.4 查看来源详情与时间含义

切回全部记录，在每条事件卡片点击“查看来源详情”。应看到原始摘录含构造声明、证据ID、来源名称及TXT文件名、来源字段与单位、时区Asia/Shanghai、首次发布时间、首次可得时间、取数时间、质量说明及采用字段。

- 来源类型为 `user_provided`，质量为 `unverified`，记录 `data_mode=constructed`、`is_constructed=true`；用户入口不产生 `provider_api` 或 `verified`。内置固定案例仍是synthetic，与本次用户导入来源不同。
- 精确时间依次为 `2025-03-10T09:30:00+08:00`、`2025-03-10T18:00:00+08:00`。仅日期记录保存 `published_date=2025-03-10`、`published_at=null`，first_available.at也是null、precision为date。
- `fetched_at=null`，页面写“未取数（本地输入/导入不冒充供应商取数）”；录入不是接口取数。
- “原始字段 / 已采用值”中的created_at/updated_at是本次实际录入管理时间，导入批次imported_at也是实际操作时间，不能预填成2025年，也不能替代历史首次公开时间。UUID及管理时间以实际操作为准，不预设固定值。
- 发布时间指原始版本首次公开；首次可得时间依据该历史时间，录入时间指今天何时存入浏览器。历史版本确认只是用户声明，不把unverified升级为verified，也不能补足仅日期缺少的小时。当前修订文字即使页面保留旧发布日期，没有当时版本也不能用于证明事前可知。

可选版本边界验收：最后另外录入一条“构造验收：旧日期未确认版本”，摘录仍使用event-before.txt，其余按事前材料填写，**不勾选**版本声明。预期归类时间未知，不进事前筛选。该操作增加第6条记录，完成基本5条检查后再做，不能沿用1/3/1数量。

交易详情应保留CSV源文件/行号、数量股、价格元/股、费用元、unknown首次可得时间；不能将成交时间或导入时间伪装成原交易文件历史可得证明。需要时点击“下载当前字段数据备份”保存本次结果；刷新后应保留三份事件及其构造声明。

## 11.5 现金口径与费用缺失

先在全部记录下检查“持仓过程与现金口径（事后总览）”：一个DEMO001过程，两笔交易，持仓归零，显示“交易记录已闭合（待完整性确认）”。买入成交额1000.00元、卖出900.00元、已录入费用合计10.00元、费用前盈亏-100.00元、现金净盈亏-110.00元，均是当前已录入交易的**暂算**。金额由整数分计算；尚未确认期初无持仓/无遗漏，不能宣称完整投资收益。

“公司行动口径（本页临时选择，不保存）”默认“未知，待确认（仅暂算）”。在纯构造案例中可选“我确认不存在影响现金流或股数的公司行动”；仍是用户声明且暂算。可选“存在分红、拆股、送股、配股等公司行动”，预期阻止简化盈亏。选择不是持久化证据，刷新或替换数据后需重选。

完成事件检查和所需备份后，仍选构造CSV入口，上传 `trades-missing-fee.csv`。两行fee均为空，其他值与上表完全相同。预览应有两笔费用缺失警告，允许确认导入。点击“确认整批导入并替换当前数据”，同意整批替换：先前事件会被清除，这是已有替换规则。

预期仍为买入1000.00元、卖出900.00元、费用前盈亏-100.00元；两笔fee=null，缺费2笔，总费用和净盈亏未知。已知费用小计0.00元只表示没有已知费用项，**不等于总手续费为零**。净盈亏应显示“未知 / 不计算：费用缺失、未清仓或公司行动限制”，不能出现准确净收益-100.00或沿用-110.00。这次导入没有补事件、日线、报告或学习清单。
