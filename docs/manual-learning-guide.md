# 清单候选与下一次决策操作指南

在原项目目录`D:\AI PM\Projects\investment-review`运行`npm.cmd run dev`，打开终端地址，在首页“04 学习清单与下一次决策”操作。没有云同步、登录或服务器保存；不同浏览器、不同网站地址（含localhost与部署站点）各自保存。导出备份包含用户文本与来源快照，请自行保管；不包含环境Key。

## 1. 选择报告候选并编辑

1. 沿用`manual-review-guide.md`完成A冻结及B校验保存。当前没有有效B时，“选择当前报告候选”不可用；已有清单和决策仍可独立查看。没有学习条目的B不会补造条目。
2. 点击“选择当前报告候选”。只形成**未保存草稿**；默认不采用任何条目，同一来源已有清单时选择现有清单，不重复添加。
3. 在“选择清单”选模板，填写“清单名称”“适用范围”“适用证券（可空）”“适用范围说明”。范围为来源持仓过程、指定证券或一般记录检查；这些由用户决定，不表示程序建议交易。
4. 逐项勾选“采用检查项：1”等，以选择下次记录使用的条目；“已人工检查：1”等只记录人工检查状态，不表示来源已verified。可编辑“候选学习问题”“学习依据”“待核验材料（每行一项）”。改写后保留“用户编辑状态：已编辑”，原B输出不变。
5. “查看清单来源与证据快照”展示报告ID、包ID、持仓过程/修订、决策ID、学习ID、关联finding ID及引用证据ID/原记录ID/字段路径/质量/构造标签。证据版本沿用原包修订，不能换成当前修改后的字段。没有引用的缺口问题明确显示无证据引用。
6. “上移条目”调整顺序；“删除条目”须在弹窗确认。删除只影响清单草稿，不删原报告或已有下一决策快照。
7. 点击“确认保存清单”。只有校验、写入和回读成功才显示“清单已确认并保存到当前浏览器”。刷新应恢复内容、选择、勾选、编辑状态及适用范围。新增模板从版本1开始；内容改动再次保存递增版本。保存不表示模型解释已证明。

允许“新建无报告来源清单”及“添加无来源检查项”，但会明确显示缺少报告来源。该条目`origin:null`，不补造证据ID。保存前将默认问题改为实际检查问题。全部条目不选仍可保存模板，但不能开始下一决策。

## 2. 下一次决策记录

1. 先保存所有草稿，勾选至少一项“采用检查项”，再点击“开始下一次决策记录”。新记录立即保存为draft，固定清单ID、版本、范围、有序内容、来源和用户编辑状态；不生成买卖建议或计划动作。
2. 若来源过期、缺失或当前无法核对，先勾选“我确认沿用过期或当前无法核对的来源（含缺来源条目），保留限制”。不确认则明确拒绝。沿用后仍保留过期/未确认标签，不变成当前有效报告。
3. 在“下一次决策记录”填写“决策理由”“反证条件”；逐项选“检查状态：1”等（未检查、满足、未满足、不适用），填写“检查说明：1”和“用户证据文本或链接：1”。仅按普通文本保存，不访问链接或调用模型。
4. 点击“保存决策草稿”，刷新应恢复。点击“完成并保存决策记录”要求理由、反证条件非空且所有条目已检查，不适用项必须说明原因；条件不足则报错，不假完成。
5. 完成后输入锁定。要继续编辑，先点击“退回草稿并保存”。此操作成功后才能编辑并再次保存。
6. 通过“选择决策记录”查看已保存记录。后来编辑清单模板，旧记录仍显示原问题和原版本；删除模板后显示“来源模板已删除”，原快照及引用继续保留。

这是决策记录工具；勾选满足、不适用或完成记录均不表示可以买入、卖出或提供投资结论。没有新交易执行入口。

## 3. 导出与导入

1. 点击“导出清单与决策备份”，下载`learning-board-backup.json`。保存内容包括清单、下一决策、原A/B包与JSON、完整证据快照及来源ID/版本。文件格式`investment-review-learning-backup-v1`，内部`learning-board-v1`，不替换原字段或复盘格式。
2. `persistence:saved`表示导出的是已保存内容；`unsaved_draft`表示含页面未保存修改，**导出不等于本地保存成功**。缺来源条目在文件`warnings`中明确提示，origin仍为null。删除模板后来源档案仍随旧决策导出。
3. 展开“导入清单与决策备份”，先导出现有备份。用“上传清单JSON备份”选择本页UTF-8 JSON，或在“粘贴清单JSON备份”粘贴全文。
4. 点击“校验清单备份”。界面显示清单/决策/来源数量及缺来源条目数量，此时**尚未导入**。只接受本阶段格式，不把旧learning-candidates.json下载文件伪装成完整备份。
5. 点击“确认替换并保存备份”，在弹窗确认**整体替换清单与决策**。原始交易、用户证据及A/B存储不被替换。只有写入回读成功才显示导入成功，刷新可恢复。
6. 导入校验完整Schema、重复键/ID、包哈希、报告引用、冻结A绑定、清单/决策快照版本及编辑标记。程序按来源交易重算现金指标并核对交易/指标快照，不能通过修改金额后重算哈希绕过口径。导入来源须对当前本地报告重新核对；导入不自动升级当前有效或verified。

## 4. 错误与保存限制

- 非法/围栏/重复键JSON、错误格式、未知字段、伪造引用/哈希、来源声明缺失、决策快照不符：显示“清单操作错误”，不覆盖原已保存数据，不修补为成功。缺少来源声明可显式使用origin:null；已有origin却找不到报告/学习条目则拒绝。
- 浏览器存储不可用或容量不足：明确未保存，保留页面草稿，使用导出保管。若初次读取失败或数据损坏，不能盲目覆盖未知原记录；先导出本页草稿，再解决浏览器权限/原备份问题并刷新。不会自动清空原数据。
- 双标签页修改：暂停保存，先导出草稿再刷新；有读取比较和写入回读检查，但localStorage不提供数据库事务保证。
- 输入文件和本地清单总容量上限8MiB；最多25份报告来源、100份模板（每份100项）、200份决策。单段文本最长2000字符。超限明确拒绝，不截断或丢弃来源；格式化导出超限时尝试紧凑JSON，仍超限则报错。
- 所有文本按普通文本显示，不执行JSON中的字符串或HTML。候选仅在明确保存后持久化；未保存编辑刷新会丢失，可导出带unsaved_draft标记的备份。

本阶段存储键`investment-review:learning-board:v1`独立于交易与手动复盘键。没有全项目备份合并/旧格式迁移、云同步或生产部署验证。真实行情仍unavailable，两次网络失败不解释为无权限，不请求真实模型或供应商。

## 5. 验证范围

`npm.cmd run test:learning`验证来源/版本/编辑/不可变快照/JSON/存储边界；`tests/browser/learning.spec.ts`通过构造夹具的有效B走真实清单按钮、下载、上传、刷新、完成/退回草稿及故障mock。构造测试回复不是模型实际调用。实际命令、退出码和数量见STATUS最新清单阶段记录；不沿用此前用户人工验收作为新功能已人工验收的证据。
