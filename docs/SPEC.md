## 1. 产品目标与核心任务

投资者通常只记得盈亏，却难以还原当时的信息、假设、行为和后续变化。本产品帮助用户复盘一段历史持仓过程，将交易记录、当时理由、日线行情和事件对齐到时间线，区分事前可知与事后信息，并将复盘中的过程改进沉淀为下一次决策清单。

产品必须形成以下可运行主链路：

1. 导入交易或打开明确标记的构造案例。
2. 识别单只股票的一段持仓过程，并检查完整性。
3. 查看程序计算的交易指标，补充理由和事件。
4. 获取行情，选择具体决策，查看时间分类和原始证据。
5. 先完成事前决策评估，再完成完整复盘。
6. 核验解释与行为偏差假设，将学习建议编辑为清单。
7. 使用清单创建下一次决策记录。
8. 刷新后恢复工作，支持完整备份与恢复。

第一版只做历史记录和决策过程学习，不输出买卖建议，不执行交易。

## 2. 用户、复盘单位与范围

### 2.1 用户

目标用户为希望整理个人历史投资决策、检查判断过程和积累学习清单的个人投资者。无需登录，不采集姓名、手机号、券商账号。

### 2.2 复盘单位

复盘单位为 `Episode`：同一股票从零持仓开始买入，经过可能的加仓、减仓，直到再次归零的一段独立持仓过程。

- 一段过程可以有多笔交易。
- 同一股票清仓后再次买入，属于新过程。
- 多只股票分别识别，不跨股票合并。
- 第一版仅处理一个匿名账户的普通 A 股现金买卖记录，币种固定 `CNY`，数量单位为股，价格单位为元/股，费用及金额单位为元。
- 不处理融资融券、做空、衍生品或跨账户汇总。
- 未清仓过程可以查看和补充资料，但不能进入正式完整复盘。
- 真实股票代码采用六位数字及 `.SH`、`.SZ` 或 `.BJ` 后缀。格式通过不代表标的存在；真实源仍须校验。名称为用户填写的展示文本，不冒充官方名称。

### 2.3 数据模式

| 模式 | 交易及理由 | 行情及事件 | 页面要求 |
|---|---|---|---|
| `real` | 用户导入或填写，真实性未自动验证 | 行情来自真实接口，事件手动录入 | 显示来源和限制 |
| `constructed` | 内置构造案例 | 全部为明确标记的演示数据 | 持续显示构造标记 |

真实模式不得静默回退到构造模式。构造模式不得请求真实股票接口。真实数据与构造数据不得合并为同一持仓过程。

## 4. 核心数据模型

### 4.1 通用约定

- 数据协议版本固定 `schema_version: "1.0"`；本地主键名称另见第 15 节。
- 业务 ID 使用稳定唯一字符串，如 UUID，不能以数组下标作为业务 ID。
- 精确时间使用带时区的 ISO 8601 字符串；展示和业务日期按 `Asia/Shanghai`。
- 仅日期使用 `YYYY-MM-DD`，不得补造具体时刻。
- 未知值使用 `null` 或明确的状态枚举，不得用零或空时间代替。
- `created_at`、`updated_at` 为当前录入管理时间，不能当作历史形成或公开时间。
- 用户输入来源不等于真实性证明；备份和证据保留该限制。
- Decimal 为十进制字符串；正数、不超过 6 位小数；费用允许零。交易数量为正整数。所有数值均拒绝非有限值、指数记法和混入单位的文本。

### 4.2 交易 `Trade`

| 字段 | 类型 | 规则 |
|---|---|---|
| `trade_id` | string | 稳定唯一 |
| `batch_id` | string | 来源导入批次 |
| `source_row` | integer | 原 CSV 记录起始行号，表头为第 1 行 |
| `symbol` | string | 规范股票代码或内置 `DEMO001` |
| `name` | string | 展示名称，可为空 |
| `trade_date` | date string | 上海日期 |
| `trade_at` | datetime string / null | 精确时间；日期精度时为 null |
| `time_precision` | enum | `datetime` / `date` |
| `side` | enum | `BUY` / `SELL` |
| `quantity` | integer | 正股数 |
| `price` | Decimal | 正成交价格 |
| `fee` | Decimal / null | 非负实际总费用；未知为 null |
| `same_day_order` | integer / null | 同股票同日的明确顺序 |
| `order_confirmed` | boolean | 顺序是否已确认 |
| `data_mode` | enum | `real` / `constructed` |
| `created_at`、`updated_at` | datetime string | 当前管理时间 |

费用指用户账单中的实际总费用。程序不推算佣金、税费、最低收费或缺失费用。

### 4.3 持仓过程 `Episode`

包含 `episode_id`、`symbol`、`name`、`data_mode`、有序 `trade_ids`、`start_date`、`end_date`（未清仓为 null）、`status`、`blocking_reasons`、`revision`、`created_at`、`updated_at`。

完整性字段：`opening_position_confirmed`、`trades_complete_confirmed`、`corporate_action_status`（`unknown` / `none_confirmed` / `present`）。确认需记录当前确认时间；它不是历史决策证据。

状态：`pending_order`、`invalid`、`open`、`pending_confirmation`、`eligible`。`eligible` 仅表示满足本产品正式复盘条件，不表示信息已完整或分析正确。

### 4.4 理由 `Reason`

包含 `reason_id`、`episode_id`、`trade_id`、`record_type`（`contemporaneous` / `recollection`）、`judgment`、`expected_evidence`、`invalidation_condition`、`source_excerpt`、`source_name`、`source_url`（可为 null）、`formed_date`、`formed_at`、`time_precision`（`datetime` / `date` / `unknown`）、`historical_version_confirmed`、`has_time_conflict`、`created_at`、`updated_at`。

`formed_*` 表示原理由的历史形成时间，由用户明确填写。事后回忆记录当前回忆内容和录入时间，不反推其当时已存在。可以保存多个来源理由；没有理由时显示缺失，不能自动补写。

### 4.5 事件 `Event`

包含 `event_id`、`episode_id`、`symbol`、`title`、`excerpt`、`source_name`、`source_url`、`occurred_date`（可为 null）、`published_date`、`published_at`、`time_precision`、`historical_version_confirmed`、`has_time_conflict`、`data_mode`、`created_at`、`updated_at`。

仅公开发布时间决定时间分类。发生时间、报告期、网页当前更新时间不能替代公开时间。手动填写须展示“用户录入，未自动核验原文版本”。链接仅接受 `http` / `https`。

### 4.6 行情 `MarketSnapshot` 与 `MarketBar`

快照包含 `market_snapshot_id`、`episode_id`、`symbol`、`source_name`、`source_url`、`fetched_at`、`upstream_request_id`、`upstream_data_timestamp`（可为 null）、`requested_start_date`、`requested_end_date`、`coverage_start_date`、`coverage_end_date`（空结果为 null）、`warnings`、`bars`、`data_mode`。上游时间戳不替代历史公开时间。

日线包含 `bar_id`、`symbol`、`trade_date`、`open`、`high`、`low`、`close`、`volume`、`turnover`、`currency: "CNY"`、`adjust: "none"`、`market_snapshot_id`。价格为正且 OHLC 关系成立，量额非负，日期唯一。构造日线也必须通过同样字段校验。

### 4.7 证据包与报告

- `EvidencePackageSnapshot`：保存包 ID、阶段、完整输入、证据快照、规范化哈希、持仓版本、选定交易、创建时间和 schema 版本；创建后不可变。
- `ValidatedReport`：保存报告 ID、阶段、包 ID、持仓 ID、版本、选定交易、原始合规 JSON、导入时间、来源标记（`manual_import` / `preset_example` / 后续 `api`）和人工核验记录。
- 报告必须引用其原包中的快照，不能在查看旧报告时换成当前字段。

### 4.8 清单与下一次决策

`ChecklistTemplate` 包含 `checklist_id`、`name`、`version`、有序条目、来源持仓 ID、来源报告 ID、来源学习条目 ID、来源过期标记、创建及更新时间。

清单条目包含 `item_id`、`question`、`why`、`required_evidence`。允许用户添加没有报告来源的条目。

`NextDecision` 包含 `decision_id`、`symbol`、`name`、`planned_action`（`BUY` / `SELL` / `HOLD`）、`judgment`、`invalidation_condition`、清单 ID 和版本、不可变清单内容快照、条目回答、`status`（`draft` / `completed`）、创建及更新时间。回答状态为 `unanswered` / `met` / `not_met` / `not_applicable`，并包含 `note` 和用户填写的证据文本或链接。

### 4.9 导入批次与本地根对象

`ImportBatch` 包含批次 ID、文件展示名、导入时间、模式、被采用记录行号、重复处理决定和同日顺序确认。无需保存 CSV 全文。

本地根对象包含 `schema_version`、`document_revision`、`updated_at`、`import_batches`、`trades`、`episodes`、`reasons`、`events`、`market_snapshots`、`evidence_packages`、`reports`、`checklists`、`decisions`。根修订用于多标签页冲突检测，持仓修订用于报告过期检测，二者不能混用。

## 5. CSV 导入契约

### 5.1 文件与表头

仅接受 UTF-8（允许 BOM）的 `.csv`。单文件最大 2 MB、最多 5,000 条交易。支持标准 CSV 引号和转义；拒绝无法可靠解码的文件，并提示转为 UTF-8。

标准表头：

```csv
symbol,name,trade_date,trade_time,side,quantity,price,fee,same_day_order
```

| 字段 | 必需 | 格式与空值 |
|---|---|---|
| `symbol` | 是 | 例如 `600519.SH`，去首尾空格、转大写 |
| `name` | 否 | 最多 100 字符 |
| `trade_date` | 是 | `YYYY-MM-DD`，真实有效日期 |
| `trade_time` | 否 | `HH:mm:ss`，按上海时间；空为日期精度 |
| `side` | 是 | `BUY` / `SELL`，可规范化大写 |
| `quantity` | 是 | 正整数，不自动乘以 100 |
| `price` | 是 | 正十进制数，元/股 |
| `fee` | 否 | 非负十进制数，空表示未知，`0` 表示明确零费用 |
| `same_day_order` | 否 | 正整数；同股票同日不能重复 |

表头缺失、重复或存在未知非空字段时拒绝解析，提示使用模板。空白记录可以忽略，须显示忽略数量。不得悄悄猜测字段含义、金额单位、日期格式或交易方向。

真实导入入口拒绝 `DEMO001`。提供单独标记“构造 CSV，仅用于演示”的导入入口，仅允许构造代码；不能导入真实和构造混合文件。

### 5.2 解析预览

正式导入前展示规范化结果、原行号、错误、警告、股票数量、交易数量和拟识别的持仓过程。错误格式至少包含 `row`、`field`、`code`、`message`、`suggestion`。

有错误、重复决定未完成或同日顺序未确认时，禁用正式导入。第一版采用整批导入成功或失败，不默默跳过错误记录。用户可以修改源文件重新导入。

### 5.3 疑似重复

对同股票、日期/时间精度、方向、数量、价格、费用相同的记录提示疑似重复，包括批次内和已有记录之间的重复。不能仅因字段相同自动删除，真实交易可能相同。

用户逐组选择“保留全部”或明确排除指定行，记录决定。用户重复上传同一文件也必须显示该确认。被排除行保留导入决定，不进入交易和计算。

### 5.4 同日顺序

- 同股票不同日期按上海日期排序。
- 同日全部为精确时间且时间不同，可以按时刻排序。
- 日期精度、精确时间重复或精度混合的同日记录，必须确认全部记录的实际先后。
- 可提供按 CSV 行序的候选顺序，但用户必须明确确认；原始行序不自动等于实际成交顺序。
- 明确精确时间与手动顺序矛盾时拒绝，提示修正。
- `same_day_order` 只能证明执行顺序，不能把日期精度成交自动变成事前已知的精确时间。

### 5.5 正式写入

导入前将新记录与同模式、同股票的已有记录共同预览并重新检查。不能把已有未清仓过程后续卖出误识别为新的先卖后买过程。

不受影响的持仓保持 ID；已有未清仓过程追加交易时保留 ID 并递增版本。若历史插入改变已保存过程的边界或归属，显示影响的过程和报告，用户确认后再提交；旧包和旧报告保留旧快照。不得在后台无提示重组已经保存的复盘。

正式导入必须在本地写入成功后显示成功；失败不提交半个批次。

## 6. 持仓识别与完整性

### 6.1 识别算法

以同模式、同股票的已确认有序交易为输入，从持仓 `0` 开始：

1. 零持仓时遇到买入，创建新过程。
2. 买入加数量，卖出减数量。
3. 过程中归零则关闭当前过程；下次买入创建新过程。
4. 卖出超过当前数量，标记负持仓和无效，不通过后续买入抵消错误。
5. 输入结束仍为正持仓，标记 `open`。
6. 顺序未确认则标记 `pending_order`，不生成正式完整过程。

先卖后买、负持仓或可能缺少期初持仓时，展示真实记录和阻塞原因。不得补造期初买入、调整数量或伪造清仓。

### 6.2 正式复盘条件

同时满足以下条件才能生成正式两阶段复盘包：

- 执行顺序已确认；
- 无负持仓，最终归零；
- 用户确认首次买入前没有该股票持仓；
- 用户确认本段交易没有遗漏；
- 用户确认本段不存在影响现金流或股数的公司行为。

公司行为未知时标为 `pending_confirmation`。确认存在分红、送股、配股等本版不支持的公司行为时，不进入标准正式复盘，保留记录并说明口径不支持。

费用缺失、理由缺失、事件或行情部分缺失可以在满足上述条件后开展受限复盘，但证据包和报告必须明确限制，不得输出缺失的净指标或确定性解释。

### 6.3 计算与完整性分开

可以展示未完成过程的交易额、已录入费用和当前持仓，但不能将净现金流显示为已实现完整盈亏。尚未确认完整的闭合记录可显示明确标为“仅依据已录入交易”的暂算值，不得标为完整投资收益。

## 7. 指标与计算口径

### 7.1 标准指标

设买入成交额为 `B = Σ(买入数量 × 买入价格)`，卖出成交额为 `S = Σ(卖出数量 × 卖出价格)`，买入费用为 `F_buy`，卖出费用为 `F_sell`。以下盈亏口径用于确认完整、最终归零且无本版不支持公司行为的过程：

| 指标 ID | 名称 | 公式 / 口径 | 单位 |
|---|---|---|---|
| `buy_amount` | 买入成交额 | `B`，不含费用 | 元 |
| `sell_amount` | 卖出成交额 | `S`，不含费用 | 元 |
| `gross_pnl` | 不含费用交易盈亏 | `S - B` | 元 |
| `total_fees` | 费用合计 | `F_buy + F_sell`，有任何费用缺失则未知 | 元 |
| `net_pnl` | 交易净盈亏 | `S - B - F_buy - F_sell` | 元 |
| `gross_return` | 不含费用简单交易收益率 | `(S - B) / B` | % |
| `net_return` | 含费用简单交易收益率 | `(S - B - F_buy - F_sell) / (B + F_buy)` | % |
| `avg_buy_price` | 平均买入价 | `B / 总买入数量`，数量加权、不含费用 | 元/股 |
| `avg_sell_price` | 平均卖出价 | `S / 总卖出数量`，数量加权、不含费用 | 元/股 |
| `holding_days` | 持有跨度 | 最后清仓日期减首次买入日期，同日为 0 | 自然日 |
| `final_quantity` | 最终持仓 | 总买入股数减总卖出股数 | 股 |

这里的简单交易收益率以累计买入资金为分母，不考虑资金占用时长与多次资金周转，不是账户收益率、年化收益率或资金加权收益率。

### 7.2 缺失与舍入

- 任意一笔 `fee = null` 时，`total_fees`、`net_pnl`、`net_return` 为未知；显示已知费用小计及缺失笔数，但不得称为总费用。
- 不含费用指标仍可显示，其完整性限制必须可见。
- 不按市价估算未卖出部分，也不以末日收盘价假定清仓。
- 全过程使用未舍入的十进制值计算，展示时采用四舍五入：金额和平均价 2 位、收益率 2 位；交易原始价格保留输入精度。
- 分母为零或所需输入不成立时显示未知及原因，不输出 Infinity / NaN。
- 不推算税费、不增加分红，不宣称与券商或税务账单完全一致。

### 7.3 指标证据

每项指标包含 `metric_id`、`value`（十进制字符串或整数，未知为 null）、`unit`、`formula`、`input_trade_ids`、`dependency_evidence_ids`、`limitations`、`status`（`known` / `unknown` / `provisional`）。程序负责计算和展示，AI 只引用指标 ID。

## 8. 时间规则与后见之明控制

### 8.1 截止时间

每次事前评估仅针对一笔选定交易，默认首次买入。

| 交易精度 | `cutoff_at` | `cutoff_basis` |
|---|---|---|
| 精确时间 | 实际成交时刻 | `trade_datetime`，评估成交之前的可知信息 |
| 仅日期 | 交易日期上海时间 00:00 | `trade_date_start`，保守采用该日前的信息 |

日期精度交易的零点只是保守评估边界，不是补造实际成交时刻。UI 必须明确说明。

### 8.2 时间分类

| 分类 | 含义 |
|---|---|
| `prior` | 已证明可获得时间严格早于截止时间 |
| `post` | 已证明可获得时间晚于或等于截止时间 |
| `unknown` | 发布时间未知、版本未核实、时间冲突，或精度不足以判断 |

严格规则：

- 精确时间必须满足 `available_at < cutoff_at` 才属于事前可知。
- 与截止时间相同的信息不算事前可知。
- 仅日期信息按该日完整时间区间判断：上海时间 00:00:00.000 至 23:59:59.999。
- 整个日期区间结束于截止时间之前，才属于事前可知。
- 整个区间起点晚于或等于截止时间，属于事后信息。
- 日期区间跨越截止时间，属于时间未知。
- 不能把仅日期的公告补成当天 00:00，以使其进入事前证据。

时间已知但发现来源冲突或无法核实对应历史文本版本的记录，标为 `unknown`，保留冲突说明，排除事前包。单纯用户选择“当时记录”不足以绕过形成时间和版本检查。

### 8.3 各类数据的规则

**交易：**

- 当前交易的最终成交价、数量、费用及之后的交易结果不进入其事前评估包。
- 明确发生在截止时间前的历史成交，可作为过去执行事实。
- 同日日期精度交易即使顺序已确认，也不能自动视为截止时间前已知。

**理由：**

- 当时记录且形成时间明确早于截止时间，才可用于还原当时判断。
- 事后回忆永远以回忆身份保存，不作为已证明的当时事实。
- 修改时间和当前录入时间不能代替原记录形成时间。
- 同一原记录如果后来被修改，用户须明确摘录对应的历史版本；否则标为无法核实。
- 阶段一只使用选定交易的合规当时理由，以及确属此前交易的合规历史记录，排除之后交易的理由。

**行情：**

- 当日完整日线不得进入当日盘中决策的事前包。
- 日期精度交易只允许使用此前日期的日线。
- 第一版统一仅将决策日期之前的已结束日线作为事前行情，不使用同日日线推断盘中状态。
- 获取时间用于标明当前数据快照，不当作历史公开时间。
- 历史日线无历史版本留存证明时，注明“当前获取的历史行情”。程序只能按历史交易日期保守控制可见范围，不能声称已还原当时的数据版本。

**事件：**

- 使用公开发布时间分类，不使用发生时间、报告期、网页当前更新时间代替。
- 未知发布时间不得进入事前包。
- 修订后的文本不能仅凭初次发布时间认定为当时已公开的文本。
- 用户不能核实文本版本时，标为时间未知。

### 8.4 展示与 AI 输入必须一致

- 事前视图只显示 `prior` 信息。
- 事后信息和时间未知分别显示数量和入口。
- 时间未知默认不参与解释性结论。
- 不能只在页面隐藏事后数据，却把它们发送给事前评估模型。
- 切换决策交易后，重新计算分类和证据包。
- “事前可知”表示时间上可能获得，不表示用户实际看过或使用过。
- 阶段一的限制说明也须过滤，不能通过“已知缺口”泄露最终盈亏、后续交易、清仓结果或后续事件内容。

## 9. 行情与事件对齐

### 9.1 时间线范围

默认展示首次买入前 30 个自然日、完整持仓区间及清仓后 7 个自然日。

用户可以缩小查看区间，不支持无限扩大历史范围。单次真实数据请求最多覆盖 366 个自然日（含起止日期）。默认范围超过限制时，要求选择不超过该上限的子区间，不自动大量拆分请求。

过长持仓过程仍可计算交易盈亏；行情只显示被明确覆盖的区间，并标注缺口。未清仓过程不生成清仓后区间。

### 9.2 对齐规则

- 横轴使用上海日期。
- 行情显示收盘价折线，交易显示买卖标记。
- 点击标记查看真实成交时间、价格、数量、费用、理由及时间精度。
- 交易标记的价格来自成交记录，不来自收盘价。
- 同一天多笔交易在详情中分别显示，不合并成交记录。
- 事件按发布时间定位；没有发布时间时放入“时间未知”列表。
- 事件没有对应日线时仍按实际日期显示，不擅自移到上一或下一交易日。
- 缺失日线显示断点或缺口提示，不前向填充。
- 不将非交易日无行情认定为接口失败。
- 无法判定缺口原因时显示“该日期无返回数据，原因未核实”，不直接认定停牌；未接入交易日历时不得猜测缺失交易日数量。
- 真实模式下没有事件，显示“尚未录入事件”，不得自动生成事件。
- 仅有历史日线不能还原盘中走势；UI 不暗示具备该能力。

## 10. 页面功能

### 10.1 首页 `/`

显示新建复盘、导入 CSV、打开构造案例、已保存的持仓过程列表、清单入口、下一次决策入口、备份与恢复入口。

列表展示股票、期间、交易笔数、完整性状态、数据模式和报告状态。构造案例按钮标注“构造案例，仅用于演示”。真实数据源状态显示“未配置 / 可请求 / 最近调用成功 / 调用失败”；配置存在只表示可请求，不能直接标为接入成功。

### 10.2 导入页 `/import`

提供模板下载、文件选择、解析预览、行级错误、疑似重复行确认、同日顺序确认、导入结果和持仓过程列表。

错误必须包含行号、字段及修正建议。构造 CSV 的专用入口须与真实入口区分。导入前后的保存状态必须真实。

### 10.3 复盘工作台 `/reviews/[episode_id]`

采用单页步骤式工作台，包含五个区域。

#### A. 交易与完整性

- 股票、持仓期间、交易明细。
- 盈亏指标及口径。
- 期初无持仓、交易无遗漏、公司行为确认。
- 费用补填，允许明确清空为未知。
- 持仓不完整时显示阻塞原因。

#### B. 理由与事件

- 每笔交易理由表单。
- 当时记录与事后回忆选项。
- 原记录时间、时间精度、历史版本确认和摘录。
- 事件新增、编辑、删除。
- 数据缺失和冲突提示。

#### C. 时间线与证据

- 获取真实行情按钮及查询区间。
- 行情图和交易、事件标记。
- 决策交易选择器。
- 事前可知 / 事后信息 / 时间未知过滤。
- 证据详情面板。
- 数据源、获取时间、覆盖区间和缺口。

#### D. AI 复盘

- 两阶段操作提示。
- 证据包和提示词预览、复制、下载。
- JSON 文本粘贴和 `.json` 文件导入。
- 校验结果及具体错误字段路径。
- 复盘报告和证据引用。
- 无 API 权限时显示“当前使用手动导入模式”。
- 过期报告提示和重新生成入口。
- 解释与行为偏差的人工核验入口。

#### E. 学习清单

- 将学习建议加入清单草稿。
- 编辑、增加、删除、排序条目。
- 明确确认后保存为清单模板。
- 使用清单创建下一次决策。

### 10.4 清单页 `/checklists`

展示所有已保存模板；编辑名称和条目；保存后版本递增；显示来源复盘；创建下一次决策；删除前确认。

修改或删除模板不改变已有下一次决策中的清单快照。删除模板后旧记录仍可显示原快照及“来源模板已删除”。

### 10.5 下一次决策页 `/decisions/new`、`/decisions/[decision_id]`

填写股票、计划动作、判断和失效条件；选择清单；逐条填写状态、说明和证据；保存草稿或完成记录；刷新后恢复。

完成记录要求必填业务字段有效，所有清单条目已有状态；不适用项必须填写理由。不根据勾选状态给出“可以买入”等推荐。完成后的清单内容快照不可变，回答若修改需明确退回草稿再保存。

不执行任何交易，不提供买卖推荐。

### 10.6 设置页 `/settings`

显示数据源与 AI 模式、本地保存状态；导出完整备份；导入并预览备份；清空全部本地数据，需二次确认；提示本地数据不会跨设备同步。

不提供客户端输入并保存行情密钥的表单。可以显示服务端配置状态，不能返回密钥值。

## 11. 证据模型与引用规则

### 11.1 证据记录

每次生成证据包时，程序创建不可变证据快照。

| 字段 | 说明 |
|---|---|
| `evidence_id` | 当前快照内稳定唯一 ID |
| `kind` | `trade` / `reason` / `market_bar` / `event` / `metric` |
| `record_id` | 对应业务记录 ID |
| `episode_id`、`symbol` | 所属持仓过程与股票，防止跨过程引用 |
| `values` | 可引用的字段和值 |
| `source_name` | 来源名称 |
| `source_locator` | CSV 行号、原文 URL 或记录位置 |
| `source_excerpt` | 对应摘录，可为空 |
| `time_class` | 相对当前决策的时间分类 |
| `availability_basis` | 时间分类依据 |
| `available_date`、`available_at`、`time_precision` | 日期、精确时刻和精度；未知不补造 |
| `fetched_at` | 获取时间，可为空 |
| `is_constructed` | 是否构造 |
| `excluded` | 是否因冲突或其他限制排除使用 |
| `limitations` | 真实性、时间或覆盖范围限制 |

计算指标的证据记录必须包含计算口径和依赖的交易证据 ID。完整复盘的总指标相对任一成交决策均不能被作为事前已知收益使用。

阶段一快照只保存被允许发送的证据，不把完整快照夹在附加字段中。阶段二保存完整快照及各交易的可见关系。程序创建的 ID 必须确定后才输出给模型，模型不能自行补 ID。

### 11.2 引用对象

每条引用包含：

- `evidence_id`
- `field_path`：指向 `values` 内字段的 JSON Pointer 路径，例如 `/close`。
- `usage`：`prior_basis` / `execution_fact` / `subsequent_change` / `recollection` / `limitation`，明确引用用途。

`usage` 是本规格为可执行校验补齐的字段，所有提示词、schema、示例和导入器必须一致。旧的二字段引用不得未经迁移直接导入。

程序必须验证：

1. 证据 ID 存在于对应快照。
2. 字段路径真实存在且所指值不是未知值；JSON Pointer 按标准处理 `~0`、`~1`，不得以不安全对象属性访问解析。
3. 证据属于当前持仓过程和股票。
4. 阶段一引用仅来自该阶段允许的证据，`usage` 仅允许 `prior_basis` 或 `limitation`。
5. `prior_basis` 引用必须指定涉及的决策交易，且在该次交易的 `decision_visibility` 中为 `prior`；不能直接使用相对默认交易的分类代替。
6. 事后回忆只能用 `recollection` 或 `limitation`；未知证据只能用 `limitation`。
7. 引用未被标记为冲突或排除。冲突的存在可在程序缺口中说明，但不能把被排除字段作为结论支持。

模型不能自行创建新的证据 ID、行情或事件。校验引用用途仍不能证明自然语言陈述真实遵守该用途，需保留人工核验说明。

### 11.3 结论引用要求

- 事实归纳和行为偏差假设必须至少引用一条有效证据。
- 解释假设也必须至少引用一条有效证据。
- 时间未知证据只能用于说明缺口或不确定性。
- 事后事件可以用于说明后续变化，不能用于证明当时应该知道。
- 事后回忆可以支持“用户现在回忆称……”，不能支持“用户当时确实……”。
- 行情和事件时间接近，不能直接证明因果关系。
- 关于因果的内容必须标为解释假设，并说明替代解释。
- 不得从单次交易认定用户具有稳定心理特征。
- 引用通过程序校验不代表结论语义已被证明。

### 11.4 点击引用

点击引用后显示原字段或原文摘录、来源、时间及时间精度、事前/事后/未知分类、单位和计算口径、是否构造、数据限制和有效原文链接。

旧报告显示其旧快照，不自动跳转为已编辑的当前字段。原文链接失效时仍显示已保存摘录，并说明无法打开来源。

## 12. AI 工作流与输入输出

AI 分为两个分析阶段。第一版通过复制证据包和导回 JSON 完成；后续自动调用复用同一协议。

### 12.1 接入阶段

| 接入阶段 | 行为 |
|---|---|
| 第一版手动模式 | 程序生成证据包与提示词；用户复制至外部模型；导回 JSON |
| 后续自动模式 | 有独立 API 权限后，同项目服务端调用模型；输出仍经过相同校验 |

普通聊天订阅、开发工具中的模型权限或当前会话可用模型，不视为项目拥有独立 API 权限。

第一版必须真实支持任意合规模型 JSON 的导入，不能只支持预置示例。生成提示词时附完整输出 schema，不使用尚未替换的占位符。

### 12.2 分析阶段一：事前决策评估

目的：在不展示最终结果的情况下，评估当前选定决策的证据、假设和缺口。每次只评估一笔交易，默认首次买入，不混入其他截止时点的未来信息。

#### 输入

| 字段 | 内容 |
|---|---|
| `schema_version` | 固定 `1.0` |
| `stage` | 固定 `prior_assessment` |
| `package_id` | 本次证据包 ID |
| `episode_id` | 持仓过程 ID |
| `episode_revision` | 当前证据版本 |
| `input_hash` | 程序生成的证据包哈希 |
| `decision_trade_id` | 当前评估交易 |
| `symbol` | 股票代码 |
| `action` | 买入或卖出 |
| `cutoff_at` | 截止时间 |
| `cutoff_basis` | 截止时间定义 |
| `evidence` | 仅允许的事前证据 |
| `limitations` | 不泄露未来结果的已知缺口和限制 |
| `instructions` | 评估范围和输出规则 |

不包含最终盈亏、当前交易实际成交价/数量/费用、后续行情或事件、事后回忆、之后交易及理由、最终复盘。当前交易 ID、股票、方向和截止边界仅作为评估定位元数据。

#### 输出

| 字段 | 类型 | 内容 |
|---|---|---|
| 协议元字段 | 原值 | `schema_version`、`stage`、`package_id`、`episode_id`、`episode_revision`、`input_hash`、`decision_trade_id` |
| `decision_assessment` | object | 核心判断、证据支持和未被检验的假设 |
| `process_findings` | array | 有引用的过程观察 |
| `missing_information` | array | 缺少的信息与影响 |
| `questions_to_verify` | string[] | 尚需核实的问题 |
| `limitations` | string[] | 无法判断的事项 |

`decision_assessment` 固定包含：`core_judgment: string`、`evidence_support: PriorFinding[]`、`untested_assumptions: PriorFinding[]`。核心判断仅作为有引用条目的概括，不允许新增未获支持的事实。

`PriorFinding`（同时用于 `process_findings`）固定包含：

- `finding_id`
- `statement`
- `finding_type`：`supported_observation` / `hypothesis` / `uncertainty`
- `evidence_refs`
- `qualification`：限制或解释边界

观察和假设要求至少一条有效引用；不确定性允许空引用，但必须写明不可判断的具体原因。`missing_information` 每项固定为 `{ "information": string, "impact": string }`。

不输出涨跌预测、买卖建议或盈亏结果。

### 12.3 分析阶段二：完整复盘与学习

目的：结合事前评估、真实执行和后续变化，区分事实、解释假设、行为偏差与不确定性。

必须先导入并校验当前版本、当前选定交易的阶段一结果。阶段二使用新的包 ID 和哈希，不能复用阶段一哈希。

#### 输入

| 字段 | 内容 |
|---|---|
| 协议元字段 | 与阶段一相同的元字段种类，使用阶段二包的值 |
| `stage` | 固定 `outcome_review` |
| `symbol` | 当前股票 |
| `cutoff_at`、`cutoff_basis` | 当前选定决策的评估边界 |
| `prior_assessment` | 已校验阶段一结果，保持原内容 |
| `prior_package_id` | 所用阶段一包 ID |
| `prior_input_hash` | 所用阶段一输入哈希 |
| `prior_evidence` | 阶段一原证据快照，用于解析其原引用 |
| `trades` | 本段全部交易 |
| `computed_metrics` | 程序计算指标及口径 |
| `reasons` | 当时记录和事后回忆，明确标签 |
| `evidence` | 本段完整证据快照 |
| `decision_visibility` | 各次交易对应的证据分类及依据 |
| `data_quality` | 缺失、冲突、调用失败、覆盖范围和公司行为情况 |
| `instructions` | 复盘规则及输出约束 |

`decision_visibility` 以交易 ID 为键，每项包含 `cutoff_at`、`cutoff_basis` 和按证据 ID 索引的 `{time_class, availability_basis}`。阶段二新结论只引用阶段二 `evidence`；阶段一原结果的引用通过 `prior_evidence` 解析，不篡改其 ID。

#### 输出

| 字段 | 类型 | 内容 |
|---|---|---|
| 协议元字段 | 原值 | 与阶段一输出相同的七个元字段，使用阶段二包值 |
| `summary` | string | 简要复盘 |
| `fact_findings` | array | 可被证据直接支持的事实 |
| `explanation_hypotheses` | array | 结果变化的解释假设 |
| `behavior_hypotheses` | array | 可能的行为偏差 |
| `uncertainties` | array | 缺口、冲突和无法判断的事项 |
| `learning_items` | array | 可转为清单的过程改进建议 |

事实、解释假设、行为假设与不确定性统一使用以下条目对象，所有字段必须出现：

- `finding_id`
- `statement`
- `decision_trade_id`：涉及具体决策时填写该交易 ID，否则为 `null`
- `evidence_refs`
- `metric_ids`：需要展示的程序指标 ID，可为空
- `qualification`
- `alternative_explanations`：string 数组；假设类必须非空，事实和不确定性可以为空

事实与两类假设要求至少一条有效引用。不确定性可以空引用，但必须具体说明缺口；没有记录不能伪造一个“缺失证据 ID”。引用未知证据时仅允许 `usage: limitation`。

学习条目固定包含：

- `learning_id`
- `question`
- `why`
- `required_evidence`：string 数组
- `related_finding_ids`：至少关联一个本次阶段二有效条目

事实数组允许为空，但必须在不确定性中说明证据不足。不得为了填满报告编造结论。摘要只概括下方条目，不加入额外未引用事实。

### 12.4 数值输出规则

- 盈亏、金额、价格、收益率由程序指标或证据字段渲染。
- AI 输出不设置可覆盖计算结果的数值字段。
- AI 自由文本不得新增金融数值断言。
- 需要展示数字时使用 `metric_ids` 或有效字段引用，界面在独立引用卡片中显示程序值。
- 模型不得重新计算收益率或补估费用。
- 用户输入或原文内已有数字可以在证据详情显示，不能变成未经校验的新指标。
- 导入器针对明显金额、价格、百分比、数量表达进行拦截并定位文本路径；不能声称能识别所有以自然语言书写的数值断言。报告仍需人工核验。

### 12.5 JSON 校验

固定使用严格 schema：

- 不接受缺少必填字段、错误类型或未知字段；顶层和嵌套对象都严格。
- 只接受纯 JSON 对象，不自动从长段文字或 Markdown 代码块中提取。
- 所有结论 ID 在同一输出内全局唯一；学习条目 ID 唯一。
- 单个文本字段最多 2,000 字符。
- 每个结论数组最多 20 条，学习建议最多 10 条；其余字符串或信息数组最多 20 条。
- JSON 最大 512 KB（UTF-8 字节）。证据包也限制为 512 KB；超限提示缩小行情区间或减少摘录，不静默删除必要证据。
- 字段路径、证据 ID、指标 ID、关联结论 ID 必须存在。
- `package_id`、持仓 ID、版本、哈希、阶段及决策交易 ID 必须匹配当前活跃包。
- 引用超时点、跨股票或跨持仓过程时拒绝导入。
- 非本段交易 ID、未知指标、未知关联条目、缺少替代解释均拒绝。
- 失败时显示具体字段路径及原因，不保存为正式报告。
- 导入不会修改原交易、行情、事件或计算结果。
- 已有合法报告不会被非法输入覆盖。

程序使用确定的 JSON 规范化序列化计算 SHA-256：按键稳定排序，保持数组顺序和数值表示；计算时排除 `input_hash` 自身。哈希覆盖包中其他完整内容，包括规则、版本和所用阶段一原结果。哈希用于检测内容变化，不是来源真实性认证。

修改数据后，旧包不能作为当前活跃包。切换交易后按所选交易重新选择或生成活跃包；相同版本下旧交易的报告仍可保留，但不能冒充当前交易报告。

### 12.6 人工核验

程序可核验证据是否存在、时间是否合规、结构是否正确，但无法自动证明文本中的推断成立。

报告必须显示：

> AI 内容已通过结构、引用和时间校验；解释与行为偏差仍需人工核验。

每条解释和行为偏差允许用户标记“待核验 / 认可 / 不认可”；不认可时填写理由。核验状态附着于报告和条目 ID，不回写原 AI JSON，不改变证据哈希。

未经用户确认的学习建议只能进入清单草稿，不能自动保存为正式模板。用户可以编辑草稿并明确点击保存，该操作记录其确认；不能将保存清单等同于已证明解释正确。

### 12.7 手动模式操作

1. 选择决策交易。
2. 复制阶段一提示词与证据包。
3. 提示用户在新的外部模型对话中处理，减少已知结果影响。
4. 导回阶段一 JSON 并校验。
5. 复制阶段二提示词与证据包。
6. 导回阶段二 JSON 并校验。
7. 查看报告、核验证据、编辑清单。

如果剪贴板不可用，提供文本选择与证据包下载。复制前显示数据预览及“包含交易和理由，将交给外部模型处理”。不得通过隐藏在提示词尾部的上下文夹带未来信息。

外部模型对话是否已有后续信息无法由产品控制，因此不宣称绝对消除了后见之明。

### 12.8 自动模式扩展要求

仅在用户提供独立 API 权限后启用：

- 服务端接收经过 schema 校验的证据包。
- 阶段一和阶段二独立模型上下文。
- 阶段一不传后续结果。
- 服务端生成结果后仍执行相同校验。
- 未配置时返回 `AI_NOT_CONFIGURED`。
- 不自动改用其他模型或伪造成功。
- 用户点击自动生成时明确提示会将证据包发送到已配置模型服务。

第一版无需实现自动生成按钮背后的真实模型调用，可以显示禁用状态及配置说明，不使用开发环境的模型权限代替产品 API 权限。

## 13. 真实数据源接入

### 13.1 固定接入目标与文档依据

本版选择扶摇公开文档中的 A 股历史日线 REST API。2026-10-09 已核对其官方聚合文档的历史 K 线、响应信封及错误码章节；这是文档核对，不是密钥或真实调用验证。

| 项目 | 上游契约 |
|---|---|
| Base URL | `https://fuyao.aicubes.cn` |
| 历史行情 | `GET /api/a-share/prices/historical` |
| 鉴权头 | `X-api-key` |
| 参数 | 单只 `thscode`、`interval=1d`、毫秒时间戳 `start` / `end`、`adjust=none` |
| 成功判断 | HTTP 成功且信封 `code=0` |
| 业务列表 | `data.item` |
| 日线字段 | `date_ms`、`open_price`、`high_price`、`low_price`、`close_price`、`volume`、`turnover` |

官方文档说明 `adjust` 默认值为前复权，因此本项目必须显式传 `none`。本项目的 366 天限制是产品限制，不宣称为上游上限。

依据链接：

- [扶摇文档](https://fuyao.aicubes.cn/docs/)
- [行情接口文档](https://fuyao.aicubes.cn/docs/api-reference/prices/)
- [完整聚合文档](https://fuyao.aicubes.cn/llms-full.txt)

实现时再次核对官方契约及实际权限。若文档无法打开或与实际响应冲突，记录阻塞，不猜测响应结构。

### 13.2 同项目服务端接口

`POST /api/market/history`

请求只接受 `symbol`、`start_date`、`end_date`，不接受未知字段。

服务端：

1. 校验股票格式、真实有效日期、起止先后及最多 366 个自然日。
2. 拒绝构造代码，使用固定上游地址，不接受用户指定 URL。
3. 将起日上海 00:00:00.000、止日上海 23:59:59.999 转为毫秒时间戳。
4. 强制日线、不复权，使用服务端 `FUYAO_API_KEY`。
5. 检查 HTTP 状态、业务状态及响应结构。
6. 将列表转换为 `MarketBar`，来源代码取已校验单标的请求；不伪造上游未返回的股票字段。
7. 校验 OHLC、重复日期、有限数值及非负量额；上游若返回股票字段则必须与请求一致。
8. 按上海日期在请求区间内再次过滤并排序。
9. 返回行情、来源、获取时间、上游请求 ID 和警告。

响应统一包含 `ok`、`data`、`warnings`、`error`、`request_id`。成功时 `error=null`，失败时 `data=null`；错误包含 `code`、`message`、`retryable`。

成功 `data` 固定包含 `symbol`、`bars`、`source_name`、`source_url`、`fetched_at`、`upstream_request_id`、`upstream_data_timestamp`、`requested_start_date`、`requested_end_date`、`coverage_start_date`、`coverage_end_date`。

空列表作为合法空结果显示，不生成假行情；不自动清空旧快照。用户明确选择采用新的空快照时保留旧快照并递增持仓版本。请求失败不替换现有快照，不递增证据版本，仅更新调用状态。

不得接受用户指定鉴权头或任意上游参数。拒绝上游跨域重定向，避免将鉴权头转发到其他域名。状态查询若需要，可增加 `GET /api/market/status`，只返回配置布尔值与模式，不返回密钥。

### 13.3 错误映射与调用验证

| 条件 | 本项目错误 |
|---|---|
| 本地密钥未配置 | `DATA_SOURCE_NOT_CONFIGURED` |
| 上游业务码 2001 / HTTP 401 | `DATA_SOURCE_AUTH_FAILED` |
| 上游业务码 2003 / HTTP 403 | `DATA_SOURCE_PERMISSION_DENIED` |
| HTTP 429 / 业务码 4001 | `DATA_SOURCE_RATE_LIMITED` |
| 响应结构、日期或数值不合规 | `DATA_SOURCE_SCHEMA_INVALID` |
| 15 秒超时 | `DATA_SOURCE_TIMEOUT` |
| 网络失败 | `DATA_SOURCE_NETWORK_ERROR` |
| 其他业务失败 | `DATA_SOURCE_UPSTREAM_ERROR`，保留脱敏码和请求 ID |

上述数字映射依据官方响应信封与错误码章节。不得仅以 HTTP 200 认定成功；接口级说明与通用说明不一致时，同时检查 HTTP 和业务状态。

真实接入完成必须留下脱敏记录：调用日期、股票和查询区间、HTTP 状态和业务状态、返回条数、最早和最晚日期、页面截图或操作记录、数据进入证据包的验证结果。

记录中不得出现 API Key 或受限原始数据全集。没有真实权限时将该项标为“未验证 / 阻塞”，不能把模拟响应测试写为真实调用成功。

未配置、无权限或失败时，真实模式显示明确错误。用户可以主动打开构造案例，但不得静默替换为构造行情。

### 13.4 iFinD 边界

本版不实现 iFinD MCP 接入。不能根据题目链接推断当前具有 MCP 工具、账号、Cookie、API Key 或新闻权限。README 明确记录“未接入”，不得编造接口名称或响应字段。

## 15. 本地保存、版本与备份

### 15.1 持久化

主存储键：`investment-review:v1`。

保存导入批次、交易、持仓过程、理由、事件、行情快照、AI 证据包快照、已校验报告、清单、下一次决策和结构版本。不保存密钥。无需保存原 CSV 全文，但保留原行号和采用字段。

### 15.2 保存行为

- 表单修改后自动保存，显示“保存中 / 已保存 / 保存失败”。
- 正式导入、报告导入、清单保存必须在本地写入成功后才显示成功。
- 本地保存失败时保留内存工作并提供备份导出。
- 单个存储文档限制 4 MB，按 UTF-8 字节计算；浏览器更低配额仍需捕获。
- 不承诺浏览器数据永久保留，不提供本地加密保证。
- 多标签页检测到外部修改时，阻止当前页继续覆盖并提示重新加载。
- 写入前再次核对根文档版本；通过可用浏览器锁与 `storage` 事件减少竞争，并说明 localStorage 不提供跨标签页事务保证。不能发现冲突后仍持续自动保存。
- 不在每次页面打开时重置或覆盖已有数据。
- 启动时先完成本地恢复再开放编辑；服务器渲染阶段不访问浏览器存储。

### 15.3 报告过期

以下修改使 `episode.revision` 递增：交易费用或内容修改、理由修改、事件新增/修改/删除、采用新行情快照、完整性或公司行为确认修改。

旧报告保留原证据快照，标为“已过期”，仍可查看旧引用。过期报告不能作为当前清单生成的默认来源；用户须重新生成，或明确选择沿用旧报告并保留过期标记。

切换决策交易不会改变原始数据版本，但当前 AI 包必须绑定所选交易。人工核验、清单编辑、下一次决策填写及请求失败不改变原交易证据版本。

### 15.4 备份恢复

- 导出带 `schema_version` 的完整 JSON。
- 恢复前校验结构、大小、唯一 ID 及关联关系；上限与本地文档一致。
- 校验包哈希、报告与快照关系及持仓交易归属；不读取备份中的任意脚本或执行字符串。
- 旧快照内的业务记录副本属于历史证据，不要求与当前记录值相同；引用关系按其原包解析。
- 已删除模板的决策以有效清单快照保留，不当作损坏关系。
- 显示将恢复的数据数量及“整体替换当前数据”。
- 用户确认后整体替换，不自动合并。
- 校验或写入失败保留当前数据，不先清空再尝试写入。
- 不兼容版本明确提示，不静默丢弃字段。

## 17. 安全与内容边界

### 17.1 数据与密钥

- 不将密钥放入客户端、公开仓库、URL、证据包、备份或日志。
- 不记录完整用户理由和交易数据到服务端日志。
- 本地数据仅保存在当前浏览器来源下。
- 复制或发送 AI 证据包前显示其包含交易和理由，并允许预览。
- 不收集真实姓名、手机号或券商账号。
- 证据链接仅允许 `http` / `https`，新窗口打开时防止反向控制原页面。
- API 请求固定上游域名。
- 外部摘录中的指令按数据处理，不能改变 AI 任务或系统权限。
- 用户文本按普通文本渲染，不直接注入 HTML；报告不得执行脚本、动态表达式或不受约束的 Markdown HTML。

### 17.2 报告内容

禁止确定性涨跌预测、收益承诺、直接买卖建议、根据单次交易进行人格或心理诊断、无证据的消息/事件/价格，以及将事后信息包装成事前依据。

报告固定展示：

> 本产品用于记录和复盘历史决策。AI 解释可能存在错误，请结合原始证据核验。

自动规则可以拦截结构性违规和明显违规文本，但不得宣称完全识别所有不当建议。解释类内容必须保留人工核验入口。
